# تقرير مشروع «نظام طلبات مطعم قشطة» (الحالة: ٢٩ أكتوبر ٢٠٢٦)

> هذا الملف يكفي لأي شخص (أو أي مساعد ذكاء اصطناعي) ليفهم المشروع كاملاً ويكمله.

## ١. ما هو المشروع؟
موقع طلبات **مستقل** عن الموقع الرسمي (https://qeshta-restaurant.vercel.app، وهو صفحة روابط فقط). العميل يختار أصنافه، يزيد الحشو بالسعر، يرى الشيك، يدخل بياناته، فيصل الطلب إلى **جروب تيليجرام** للمطبخ بأزرار إدارة. هدف صاحب المشروع (أحمد): تجربة لا تُنسى، مجانية بالكامل، آمنة، ولا تعرّض رقم واتساب المطعم للحظر. الطلبات المتوقعة ≤ ٥٠ يومياً. يوجد أيضاً هاتف أرضي للطلبات.

## ٢. القرارات المعتمدة (لا تُغيَّر بدون سؤال صاحب المشروع)
- الاستضافة: **Cloudflare Workers + Static Assets** (مجاني ومسموح تجارياً). استُبعد Vercel Hobby لأنه غير تجاري، واستُبعد Next.js لأن محوّلاته على Cloudflare معقدة (vinext لا يزال beta).
- قاعدة البيانات: **Cloudflare D1** (استُبعد Firestore وNeon وKV). KV غير مناسب للطلبات (تحديثات متأخرة ولا معاملات).
- البوت: **بوت تيليجرام واحد** `@QeshtaRequestsBot` (استُبعد بوت التقارير). الإرسال عبر تيليجرام وليس واتساب (لا خطر حظر).
- التحليلات: **Microsoft Clarity فقط** (المعرّف z0gxnddk3q). الحماية: **Turnstile** + Webhook secret + منع التكرار.
- التوصيل **مجاني دائماً**. لا تتبّع حالة الطلب للعميل. الدفع: كاش / محفظة / إنستا (تأكيد يدوي).
- المنيو ثابت في الكود (يُخدم كملف) لتقليل استهلاك القاعدة.

## ٣. البنية
```
public/index.html      واجهة الطلب (هوية قشطة + أصوات + Turnstile + Clarity)
public/lib/menu-data.js  المنيو الوحيد (٩٢ صنف، تُعدَّل الأسعار هنا)
public/lib/pricing.js  سلالم الأسعار والتحقق (يعمل في المتصفح والسيرفر)
src/worker.js          /api/order  و /api/tg (webhook)  وCron إعادة الإرسال
db/schema.sql          الجداول (مطبّقة فعلاً على القاعدة الحية)
data/menu.json         نسخة مرجعية من المنيو المعتمد (للاختبار فقط)
tests/                 ١٣ اختباراً (npm test = node --test)
wrangler.jsonc         إعداد Cloudflare
```
**التدفق:** العميل ← `/api/order` ← (honeypot، Turnstile، تحقق بيانات، إعادة حساب الأسعار من المنيو، حد ٣ طلبات/١٠ دقائق للهاتف) ← D1 (INSERT OR IGNORE بمفتاح فريد = منع التكرار) ← رسالة تيليجرام بأزرار ← حفظ message_id. إن فشل تيليجرام يبقى `tg_sent=0` ويعيد Cron المحاولة كل دقيقة (٥ مرات). إن فشلت القاعدة تُرسل الرسالة مع تنبيه «لم يُحفظ».

## ٥. قواعد الأسعار (معتمدة)
- معظم الأصناف «يبدأ من»: السعر الافتراضي هو الأدنى والعميل يزيد بخطوات **١٠ جنيه** (زيادة = حشو أكثر).
- **كريب (عادي/جامبو):** سلّم واحد من سعر العادي حتى قبل أول سعر للوردة؛ الاسم واللون يتحولان إلى «جامبو» عند أول سعر له. مثال شاورما ٩٠ ← ٢٩٠، وعند ٢٩٠ تظهر «آخر سعر للجامبو، والوردة تبدأ من ٣٠٠». **الوردة** سلّم مستقل: من سعرها +١٠٠. إن كان السعر لا يقبل القسمة (كرسبي ٧٥) يقفز من ٩٥ إلى ١٠٠.
- أي صنف بسعر واحد (رولات، برجر، فطير، إضافات «يبدأ من») ← من سعره حتى +١٠٠.
- «كونة» ٣٠ ثابتة · المشروبات الغازية ٢٥ ثابتة · الصوصات مجانية · «باكيت بطاطس ميكسات أصناف أخرى» **بلا سعر** (لا يدخل الإجمالي ويُكتب «السعر بالتليفون»).
- ألوان الأحجام: عادي برتقالي `#FF5A1F` · جامبو ذهبي `#FFD166` · وردة أحمر `#B3261E`.
- «برجر فحم» نوع حشو (لحم برجر مشوي على الفحم) وليس ساندوتش البرجر.
- لتغيير سعر أو سقف: عدّل `public/lib/menu-data.js` ثم `npm test` (الاختبار يقارن مع `data/menu.json`، حدّثه عند تغيير مقصود).

## ٦. البوت: الأزرار والأوامر والإدارة
- رسالة الطلب بالصيغة المعتمدة، وتحتها أزرار حسب الحالة: **جديد ← تم التأكيد ← خرج للتوصيل ← تم التسليم** (وإلغاء في أي مرحلة). كل ضغطة تُسجَّل باسم الضاغط في `order_events`، ويُحدَّث نص الرسالة. أول ضاغط يفوز ولا يتكرر.
- من يملك الصلاحية؟ المالك (`OWNER_IDS` في wrangler.jsonc، مفصولة بفواصل لإضافة مالك آخر) + الموظفون النشطون في جدول `staff`. غيرهم يرون «مش مسموح لك».
- الأوامر (داخل الجروب): `/myid` (لأي شخص: يعرض رقمه) · `/pending` أو `/pending 2` (الطلبات المفتوحة، ٥ في الصفحة) · `/staff` (القائمة) · **`/addstaff`** و **`/removestaff`** (للمالك فقط).
- **إضافة موظف:** يدخل الجروب، ثم المالك يردّ (Reply) على رسالته بـ `/addstaff` (أو يكتب `/addstaff 123456789` برقمه). **حذف:** `/removestaff` بنفس الطريقة، ثم يُخرجه من الجروب. السجل يحفظ القديم (active=0).
- الاتصال بالعميل: رقمه نص قابل للضغط في الرسالة (أزرار تيليجرام لا تقبل `tel:`).

## ٧. الأمان
Webhook لا يقبل إلا مع `X-Telegram-Bot-Api-Secret-Token` المطابق · إعادة حساب كل الأسعار في السيرفر (أي سعر خارج السلّم يُرفض) · قيود CHECK وUNIQUE في D1 · Turnstile (يتخطاه الكود فقط إن لم يُضبط السر) · honeypot · حد الطلبات لكل هاتف · أسرار خارج المستودع (`.gitignore`) · لا تتبع للعميل ولا بيانات شخصية في Clarity (راجع إعداد التعتيم، انظر ١٠).

## ٨. ما تم / ما لم يتم
**تم واختُبر (١٣ اختباراً ناجحاً):** المنيو (٩٢ صنف مطابقة حرفية) · سلالم الأسعار والرسائل عند الحدود · التحقق وإعادة الحساب · منع التكرار · الطلب والصيغة · webhook والأزرار والصلاحيات · إضافة/حذف الموظفين · جداول D1 الحية (اختبارات إدراج ورفض ثم تنظيف).

**لم يتم:** النشر على Cloudflare (يحتاج لوحة التحكم) · رفع الكود إلى GitHub (أداة GitHub طلبت موافقة ولم تصل) · إضافة المالك إلى جدول `staff` غير لازمة (يُقرأ من OWNER_IDS).

## ٩. خطوات النشر (٨ خطوات)
1. ارفع محتوى المجلد إلى `a7med7uss/Qeshta2_orders` (GitHub ← Add file ← Upload files، أو git push).
2. Cloudflare ← Workers & Pages ← Create application ← **Import a repository** ← اختر الـ Repo، اسم المشروع `qeshta-order` (يجب أن يطابق `name` في wrangler.jsonc)، أمر البناء فارغ.
3. بعد النشر ستحصل على رابط `https://qeshta-order.<حسابك>.workers.dev` (هذا هو رابط التجربة).
4. Settings ← Variables and Secrets ← أضف الأسرار الثلاثة (النوع Secret).
5. Turnstile ← الـ widget ← Hostname Management ← أضف نطاق الرابط أعلاه.
6. افتح في المتصفح (مرة واحدة): `https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://<رابطك>/api/tg&secret_token=<WEBHOOK_SECRET>` (بعدها لا يعمل `getUpdates`).
7. جرّب طلباً حقيقياً صغيراً من موبايلك، واضغط أزرار الحالة من الجروب، وجرّب `/myid` و`/pending`.
8. بعد النجاح: غيّر رابط زر «اطلب اونلاين» في الموقع الرسمي إلى رابط موقع الطلبات.

## ١٠. مهام مقترحة للإكمال
- ضع شعار قشطة محلياً بحجم ٢٥٦px (الأصلي ٤٠٩٦×٣٩٤٦ ثقيل) وصورة خلفية، وصورة مشاركة ١٢٠٠×٦٣٠ في `public/` وعدّل وسوم og. حالياً الصور تُحمّل من الموقع الرسمي.
- Clarity: من الإعدادات فعّل التعتيم (Masking) لحقول الاسم والهاتف والعنوان وتحقق منه.
- سبب الإلغاء، وتعديل الأصناف من البوت، وأمر `/today` للمبيعات (اختياري).
- نقل الموقع الرسمي من Vercel Hobby (غير تجاري) إلى Cloudflare Pages.
- حالة «مفتوح الآن» في الموقع الرسمي تقرأ ساعة جهاز الزائر؛ يجب حسابها بتوقيت القاهرة (٢ ظهراً – ٦ صباحاً).
- حدود D1 المجانية: ٥ مليون قراءة و١٠٠ ألف كتابة صف يومياً (الطلب ≈ ١٥ كتابة) = كافية جداً لـ ٥٠ طلب.
